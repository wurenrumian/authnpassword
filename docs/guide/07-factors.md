# 身份代数：因素、MFA、无密码

这一篇处理一批听起来像行话、但实际是基础概念的词：第一因素、第二因素、MFA、2FA、passwordless、step-up authentication。

看起来是术语问题，实际上是一个**计数问题**：你在数什么东西？数错了，你的 MFA 就是假的。

## 因素不是"多少个步骤"

"多因素认证"里的因素，指的是**证据的类别**，不是步骤的数量。

传统的三分法是：

| 类别 | 叫法 | 例子 |
|---|---|---|
| 你知道的 | knowledge | 密码、PIN、安全问题 |
| 你有的 | possession | 手机、硬件密钥、智能卡 |
| 你是什么 | inherence | 指纹、人脸、声纹 |

一个认证流程里出现两个步骤，但都落在同一类别，就**不是**多因素。

最典型的坏例子是"密码 + 安全问题"：两个都是"你知道的"，只是两道记忆题。攻击者拖库之后两个都能拿到，或者都能从社交工程里问出来。

另一个常见坏例子是"密码 + 邮箱验证码"：如果邮箱本身是用同一个密码登录的，那么这道验证的强度不会超过密码。

## 为什么类别不同才有意义

因为不同类别的证据**失效方式不同**。

- 密码会被钓鱼、被撞库、被拖库。
- 手机可能会丢，但丢了也不会被远程读取。
- 指纹不能改，但也不能撤销——所以它只能在本机解锁，绝不该作为网络凭据传输。

多因素的价值在于：**攻击者需要同时攻破两种不同的东西。** 如果两种东西是一起泄露的（比如都在同一个数据库里），那"两种"只是心理安慰。

严格来说，更准确的判断方式是问：**这两份证据是否会在同一次攻击中同时失守？** 如果是，就不是真正的多因素，哪怕它们分属不同类别。

## 密码学上的"MFA"和营销上的"MFA"

这中间有落差，需要说清。

**营销意义上的 MFA**：登录时多一步。很多产品把"输密码后再输一次密码"或者"回答安全问题"称为 MFA。这不成立。

**标准意义上的 MFA**（NIST SP 800-63B）：需要来自不同类别的、独立验证的认证器。规范里还区分了 AAL1/2/3 三个保证等级，AAL3 要求硬件持有物加抗钓鱼能力。

**密码学意义上的更强形态**：证据不可导出、不可重放、绑定目标。这是 passkey 那一档。

你在评估一个产品时，要问的是"它属于哪一档"，而不是"它有没有勾上 MFA 这个框"。

## 2FA 和 MFA 的区别

2FA 是多因素认证的一个特例：正好两个因素。日常口语里两个词差不多混用。

真正值得注意的是**"第二个因素保护的是什么"**。有两种完全不同的用法：

**情形一：第二因素保护登录。** 你输密码，再输 TOTP。攻击者要登进来需要两样。

**情形二：第二因素保护的是敏感操作。** 你平时用密码登录，但改密码、转账、删账号时需要再验证一次。这叫 **step-up authentication**（提升认证）。

第二种常被忽略，但它可能是更重要的。很多攻击者的目标不是"登进来看看"，而是"改掉你的邮箱/密码，然后彻底接管"。提升认证专门挡这个。

## 无密码到底是什么

"passwordless"有三个不同的意思，混在一起会让人以为这是一个东西：

**一、没有共享秘密。** passkey 是这一类。私钥不出设备，服务器只有公钥。这是最强的形态。

**二、没有密码，但有其它东西。** magic link、OTP、推送确认。你确实不用输密码，但背后可能仍有一个共享秘密（比如设备的注册凭据）。

**三、密码还在，只是不常用。** 日常用 passkey，恢复时用密码。这是过渡期的常态，也是最常见的现实。

判断标准还是第 1 篇那个：**验证方有没有你秘密的副本。** 有，那它只是"不用打字的密码"。

## 一个真正成立的 MFA 该有的样子

把前面几篇的结论收拢，一个设计良好的多因素方案大致长这样：

1. **第一因素**：密码（或者更好的，passkey）。
2. **第二因素**：passkey（抗钓鱼）或 TOTP（普遍可用）。两者最好都提供。
3. **恢复路径**：独立设计，不能比主路径弱太多。恢复码打印出来锁在抽屉里；不要只靠短信。
4. **限速与锁定**：六位码的世界里，这比算法本身更重要。
5. **提升认证**：敏感操作单独再验一次。
6. **撤销能力**：能看见并移除每一台已登录设备。

第 3 点值得单独强调。几乎所有"多因素被绕过"的真实报告，最后都落在恢复流程上：攻击者不攻密码，也不攻 TOTP，而是打客服电话，说"我手机丢了"，然后通过社工重置。

**你的安全等级等于最弱那条入口的等级**，不是最强那条的。这句话在整套文章里反复出现，因为它是唯一一条能预测事故的规律。

## 因素与凭据的对应表

| 凭据 | 类别 | 可抗钓鱼 | 可撤销 | 可复制 |
|---|---|---|---|---|
| 密码 | 知道 | 否 | 是（重置） | 是 |
| PIN | 知道 | 否 | 是 | 是 |
| 安全问题 | 知道 | 否 | 是 | 是 |
| TOTP 种子 | 知道+有（手机） | 否 | 是 | 是 |
| 短信 | 有（SIM） | 否 | 换号 | 是（SIM 交换） |
| 推送确认 | 有（已登录设备） | 部分 | 是 | 否 |
| 同步 passkey | 有 | **是** | 是 | 是（云端密文） |
| 硬件密钥 | 有 | **是** | 是 | **否** |
| 指纹 | 是什么 | 否（不能传） | 不能 | 不能 |

看一眼"可复制"那一列，就能明白为什么 passkey 那一档被认为是终点：**它是唯一同时做到抗钓鱼且私钥不可通过网络复制的组合**（硬件密钥那一行）。

## 常见混淆的三种情况

**混淆一：把"多一步"当成"多因素"。** 见上文。

**混淆二：把"生物识别"当成独立的网络因素。** 指纹本身不能传，它只是本地解锁一个密钥。所以"用指纹登录"实际上是一个 passkey 操作——指纹是解锁手段，密钥才是凭据。理解这一层，就不会去问"指纹能不能作为第二因素发给服务器"这种问题了。

**混淆三：把"设备信任"当成一个因素。** 很多系统有"记住这台设备"的功能，一个月内免验证。这不是因素，是**会话延长**。它把多因素降回了单因素，而且往往没人注意。这是企业环境里被利用最多的漏洞之一。

## 承上启下

到这里，"怎么证明"和"证明完能干什么"都清楚了。剩下的问题变成**这些东西放在哪儿、什么时候失效**——这是你会感觉最乱的一部分，因为密码管理器、KMS、TPM、agent、硬件密钥都堆在这里，它们看起来都在做同一件事。第 8 篇会把它们排开。
