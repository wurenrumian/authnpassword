# 两种材料

上一篇给了你一张清单。这一篇只处理清单底下那块砖：为什么所有凭据归根结底只有两种材料，以及这个区分到底预测了什么。

读完之后你应该能对任何一份凭据回答一个问题：**验证方手里有没有你的秘密副本。** 有，就是对称的；没有，就是非对称的。

## 对称秘密：验证方也有一份

密码是最原生的形态。你注册时交出一串字符，服务端存一份（希望是哈希过的），之后每次登录它拿你给的和我存的比。两份是一样的。

判断标准不是"它是不是一串字符"，而是**这份能力是否可以被复制**。对称秘密有一个必然的后果：任何一方持有它，就同时具备了**证明自己**和**冒充别人**的能力。服务端知道你的密码，所以服务端理论上可以冒充你；同样的道理，你知道服务端的共享密钥，就能冒充服务端。

这个对称性带来几个连锁反应，你会在后面反复遇到：

- **必须存哈希，不能存原文**。因为一旦数据库泄露，泄露的是能力本身。
- **泄露之后你无法察觉**。密钥被复制了，原件还是好的，没有任何东西会告诉你有两份存在。
- **撤销意味着换一个**。没有"吊销这一份、保留那一份"的操作，因为两份无法区分。
- **长度即安全**。熵来自随机性，而随机性来自长度。这就是为什么 API key 动辄 40 个字符，而人能记住的密码只有十来个。

## 密钥对：秘密从不出门

私钥留在你自己这里，公钥交给对方。对方要验证你的时候，不比对任何东西，而是让你对一段数据签名，再用公钥验签。

这里的关键性质是：**验签过程不会泄露任何可用于签名的东西**。公钥本身就是公开的，名字里的"公"就是这个意思。所以：

- 服务端不需要保护它存的那一份。它存的是公钥，泄露了也无所谓。
- 私钥可以在从不联网的情况下一直待在一个地方（你的磁盘、一根 YubiKey、一颗 TPM 芯片）。
- 每台机器可以有自己的一对密钥，不用共享任何东西。撤销其中一对，不影响其它的。
- 签名可以附带上下文：SSH 签的是服务端给的随机挑战，passkey 签的里面对绑定了域名。这让重放和钓鱼变得困难（第 5 篇展开）。

代价是：**非对称运算比哈希贵，密钥比密码长得多，人管不了。** 所以密钥对几乎总是被包在一个软件层里使用——ssh-agent、浏览器、操作系统钥匙串、硬件芯片。这一层不是装饰，它承担了"人不可能手抄私钥"这件事。

## 一张对照表

| 维度 | 对称 | 非对称 |
|---|---|---|
| 验证方是否持有你的秘密 | 是 | 否 |
| 网络上传什么 | 秘密本身（或它的短寿命派生） | 签名或挑战响应 |
| 截获后的后果 | 立即等同被冒充 | 通常无用（除非能重放） |
| 泄露能否察觉 | 不能 | 私钥泄露也难，但公钥是公开的 |
| 撤销粒度 | 只能整体替换 | 可以按密钥对撤销 |
| 每台设备一份 | 难（要分发同一秘密） | 容易（各自生成） |
| 能否放进硬件不可导出 | 基本不能（要在硬件内运算才有意义） | 能 |
| 计算成本 | 低 | 高（但实际影响很小） |
| 人能手工管理 | 能（短） | 不能 |

最后两行解释了为什么现实中的分布是这样：对称凭据便宜、简单、能在任何地方算，所以它们占据了"机器对机器"和"高频请求"的场景；密钥对贵、必须包一层，所以它们出现在"人的身份"和"高价值长期凭据"的位置上。

## 三个反直觉的地方

### 一、HTTPS 本身是对称的

打开浏览器访问任何网站，握手时用非对称（证书、ECDHE）协商出一个会话密钥，然后**所有数据传输都用对称加密**。原因很简单：对称快一到两个数量级。

所以"非对称"不是"更高级"，它是用来解决"如何在陌生人之间安全地建立共享秘密"这个引导问题的。一旦共享秘密建立起来了，就切回对称。这个模式在认证里到处都是：Kerberos 用长期共享密钥换短期票据，OAuth 用 refresh token 换 access token，都是同一个思路——**用昂贵的东西建立一次信任，然后大量使用便宜的东西**。

### 二、密码学强度通常不是瓶颈

几乎所有的真实入侵都发生在别的地方：钓鱼网站实时转发你的六位码、数据库没淘汰旧哈希、CI 日志里打印出了 token、员工把 PAT 提交到了公开仓库。ed25519 和 RSA-2048 谁更强，在这些事故里没有任何区别。

我提这一点是因为"选哪种材料"这个问题容易让人过度投入。材料选对比材料选强重要得多。

### 三、TOTP 的种子是对称的

很多人把"认证器 app 里的六位数"当成和非对称密钥同一类高级东西。它不是。TOTP 的种子在注册时被复制了一份给服务器（通常是二维码里的 `otpauth://` URL），之后双方各自用同一个算法算同一个数。**这仍然是一个共享秘密**，只是每次出示的函数结果不同。

它比密码强，但强的机制不是"秘密不出门"，而是"秘密每次表现为不同的值，且用过就过期"。这个区别在第 4 篇会讲透，因为它直接决定了为什么 TOTP 能被钓鱼而 passkey 不能。

## 一个能用的判据

拿到一份新凭据，问一句：**如果我现在把它抄下来发给同事，他能不能立刻冒充我？**

- 密码、PAT、API key、session cookie、恢复码：能。对称的。
- SSH 私钥、passkey、mTLS 证书：把私钥文件发出去他也能；但**仅仅把网络流量发给他，他不能**。这就是非对称的意义所在。
- 六位数验证码：只在几十秒内能，之后作废。派生类。

第二行值得停顿一下。"私钥文件发出去"当然等于泄露，任何材料都可以被交出。非对称保证的不是"不可分享"，而是**"运行时的正常使用不会产生可分享的产物"**。这一条是它全部价值的来源。

## 承上启下

材料决定了最根本的后果。接下来三篇按出示方式分成三条路：直接把秘密递出去（第 2 篇）、证明而不暴露（第 3 篇）、每次现算一个新数（第 4 篇）。这三条路覆盖了 00 篇 A/B/D 三组的全部内容。
