## 全书的主线

任何一份认证凭据，都可以用四个问题定位：

1. **材料是什么**——双方共享一份秘密，还是只有一方持有私钥。
2. **怎么出示**——直接递给对方看，对一段挑战签名，还是现场算一个短时效的数。
3. **谁在证明**——人、设备，还是一个没有人在场的进程。
4. **在哪儿、谁能替你用、什么时候失效**——存放层和生命周期。

第 3 个问题在大多数凭据清单里没有痕迹，但它决定了另一半世界长什么样。人的凭据可以靠"多要一道证明"来加固；机器不能弹窗、不能按指纹，所以机器凭据只能靠**短寿命**和**绑定具体目标**来加固。这就是为什么 PAT 这种长期有效的机器凭据在行业里正在被淘汰，换成 CI 里临时签发、几分钟就过期的 token。

## 关于准确性的约定

涉及协议的地方会标出 RFC 或标准编号。凡是"某个实现通常怎么做"而非"规范保证"的内容，会明确写成惯例。没有标号的判断是作者意见，你可以不同意。

写这套东西时尽量不省略前提。如果某处你觉得跳跃太大，那多半是省掉了一步，而不是你应该已经知道——[提个 issue](https://github.com/wurenrumian/authnpassword/issues)，我补上。
